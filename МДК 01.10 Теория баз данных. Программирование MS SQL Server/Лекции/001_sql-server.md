# Что такое Microsoft SQL Server

**Microsoft SQL Server** — система управления реляционными базами данных (СУБД), разработанная Microsoft.

СУБД отвечает за хранение, обработку и управление данными.

Что можно делать в MS SQL Server:

* сложные запросы;
* транзакции;
* серверную бизнес-логику;
* хранимые процедуры;
* функции;

# SQL и T-SQL

## Что такое SQL

**SQL (Structured Query Language)** — язык, используемый для работы с реляционными базами данных.

Например:

```sql
SELECT name, age
FROM students
WHERE age >= 18;
```

SQL позволяет описывать, какие данные необходимо получить или изменить.

Но классический SQL сам по себе не является полноценным универсальным языком программирования.

Например, в SQL нет привычной нам структуры обычной программы.

Для серверной программной логики SQL Server использует расширение SQL.

---

## Что такое T-SQL

**T-SQL (Transact-SQL)** — расширение SQL, используемое Microsoft SQL Server.

Помимо обычных SQL-запросов T-SQL позволяет использовать:

* переменные;
* условия;
* циклы;
* обработку ошибок;
* процедуры;
* функции;
* транзакции;
* управляющие конструкции.

Например:

```sql
DECLARE @age INT = 18;

IF @age >= 18
    PRINT N'Совершеннолетний';
ELSE
    PRINT N'Несовершеннолетний';
```

# SQL Server, PostgreSQL и MySQL

PostgreSQL, MySQL и SQL Server решают похожие задачи.

Однако между ними есть существенные различия.

Например:

| Возможность             | PostgreSQL     | MySQL             | SQL Server           |
| ----------------------- | -------------- | ----------------- | -------------------- |
| СУБД                    | PostgreSQL     | MySQL             | Microsoft SQL Server |
| Основной диалект        | PostgreSQL SQL | MySQL SQL         | T-SQL                |
| Основной GUI-инструмент | pgAdmin        | MySQL Workbench   | SSMS                 |
| Схемы                   | Да             | Имеют особенности | Да                   |
| Процедуры               | Да             | Да                | Да                   |
| Функции                 | Да             | Да                | Да                   |
| Триггеры                | Да             | Да                | Да                   |
| Транзакции              | Да             | Да                | Да                   |
| Оконные функции         | Да             | Да                | Да                   |

Важно понимать:

> SQL — это общий язык работы с реляционными данными, а PostgreSQL, MySQL и SQL Server имеют собственные диалекты и расширения. Поэтому SQL-код, написанный для одной СУБД, не всегда можно просто скопировать в другую.

# Экземпляр SQL Server

**Экземпляр (instance)** — отдельная работающая среда SQL Server Database Engine, к которой можно подключиться.

На одном компьютере теоретически может быть несколько экземпляров SQL Server.

Например:

```text
Компьютер
│
├── SQL Server Instance 1
│   ├── Database A
│   └── Database B
│
└── SQL Server Instance 2
    ├── Database C
    └── Database D
```

Когда мы открываем SSMS и подключаемся к SQL Server, первым делом мы подключаемся к экземпляру.

В повседневной разработке мы чаще всего будем работать с одной базой данных внутри одного экземпляра, поэтому разница может быть неочевидна.

Но при работе с SQL Server её необходимо понимать.

# База данных

**Database** — логически организованный набор данных и объектов.

Например, для колледжа можно создать:

```text
CollegeDB
```

Внутри неё будут находиться таблицы, представления, процедуры и другие объекты.

Пример:

```text
CollegeDB
│
├── Таблицы
├── Представления
├── Хранимые процедуры
├── Функции
└── ...
```

Создать базу можно с помощью:

```sql
CREATE DATABASE CollegeDB;
```

После создания базы можно переключиться на неё:

```sql
USE CollegeDB;
```

Теперь следующий запрос будет выполняться в контексте `CollegeDB`.

Например:

```sql
USE CollegeDB;

SELECT *
FROM ...
```

В SSMS базу также можно выбрать через выпадающий список над редактором запросов.

Содержит важную системную информацию об экземпляре SQL Server.

Например, сведения о базах данных и конфигурации экземпляра.

Используется как шаблон при создании новых баз данных.

Используется SQL Server для временных объектов, промежуточных результатов и других временных операций.

Для обычного учебного проекта нас в первую очередь интересует собственная пользовательская база:

```text
CollegeDB
```

# Схема

Теперь рассмотрим концепцию, которая особенно важна при переходе с других СУБД.

**Schema** — пространство имён внутри базы данных, в котором находятся объекты.

Например:

```text
CollegeDB
│
├── dbo
│   ├── Студенты
│   ├── Группы
│   └── Предметы
│
└── audit
    ├── Изменения
    └── Логи
```

Здесь:

```text
dbo
```

и

```text
audit
```

— схемы.

А:

```text
Студенты
Группы
Предметы
Изменения
Логи
```

— объекты внутри этих схем.

Поэтому:

```text
dbo.Students
```

означает:

> Объект `Students`, расположенный в схеме `dbo`.

# Схема `dbo`

При работе с SQL Server вы будете постоянно встречать:

```sql
dbo.students
```

`dbo` — стандартная схема, широко используемая в базах SQL Server.

Например:

```sql
SELECT *
FROM dbo.students;
```

Мы явно указываем схему объекта.

Можно встретить и запись:

```sql
SELECT *
FROM students;
```

Однако явное указание схемы:

```sql
dbo.students
```

обычно делает код понятнее и позволяет однозначно указать объект.

# Объекты базы данных

База данных SQL Server содержит гораздо больше, чем просто таблицы.

Основные объекты, которые мы будем изучать:

```text
Database
│
└── Schema
    │
    ├── Tables
```

## Table

Таблица хранит данные.

```text
college.Students
```

Например:

| Id | Name    | Age |
| -: | ------- | --: |
|  1 | Иван    |  18 |

## View

**Представление (VIEW)** — объект базы данных, основанный на запросе.

Например:

```sql
CREATE VIEW college.adult_students
AS
SELECT id, name, age
FROM college.students
WHERE age >= 18;
```

После этого с представлением можно работать как с объектом:

```sql
SELECT *
FROM college.adult_students;
```
---

## Stored Procedure

**Хранимая процедура** — объект базы данных, содержащий программную логику, которую можно запускать на SQL Server.

Например:

```sql
CREATE PROCEDURE college.get_students
AS
BEGIN
    SELECT *
    FROM college.students;
END;
```

Запуск:

```sql
EXEC college.get_students;
```

---

## Function

**Пользовательская функция** позволяет создавать переиспользуемую вычислительную или табличную логику.

Например, функция может получать число и возвращать вычисленный результат.

---

## Trigger

**Триггер** — специальный объект, который автоматически выполняет определённую логику в ответ на определённые события.

Триггеры будут рассмотрены после процедур и функций.

# Почему существует `NVARCHAR`

При работе с текстом в SQL Server можно встретить:

```sql
VARCHAR
```

и:

```sql
NVARCHAR
```

`NVARCHAR` предназначен для Unicode-строк.

Например:

```sql
DECLARE @name NVARCHAR(100);

SET @name = N'Алексей';

SELECT @name;
```

Префикс `N` перед строковым литералом показывает, что это Unicode-строка.

Поэтому в учебных примерах с кириллицей удобно использовать:

```sql
N'Что-то на умном!'
```

# Условная логика в T-SQL

T-SQL позволяет использовать `IF ... ELSE`.

Например:

```sql
DECLARE @age INT = 18;

IF @age >= 18
    PRINT N'Совершеннолетний';
ELSE
    PRINT N'Несовершеннолетний';
```

Можно использовать блоки:

```sql
DECLARE @age INT = 18;

IF @age >= 18
BEGIN
    PRINT N'Совершеннолетний';
    PRINT N'Доступ разрешён';
END
ELSE
BEGIN
    PRINT N'Несовершеннолетний';
    PRINT N'Доступ запрещён';
END
```

# Автоматическая генерация идентификаторов

При переходе с PostgreSQL может возникнуть вопрос: чем заменить `SERIAL`?

В SQL Server для автоматической генерации последовательных значений часто используется `IDENTITY`.

Например:

```sql
CREATE TABLE college.students
(
    Id INT IDENTITY(1,1) PRIMARY KEY,
    Name NVARCHAR(100) NOT NULL
);
```

Здесь:

```text
IDENTITY(1,1)
```

означает:

```text
начальное значение = 1
шаг = 1
```

При добавлении:

```sql
INSERT INTO college.students (Name)
VALUES
    (N'Иван'),
    (N'Мария'),
    (N'Алексей');
```

SQL Server автоматически создаст идентификаторы:

```text
1
2
3
```

То есть `Id` указывать вручную не требуется.

# Получение созданного идентификатора

При работе с приложениями часто возникает ситуация, когда нужно получить последний значение счетчика(IDENTITY)

Например:

```sql
INSERT INTO college.students (Name)
VALUES (N'Иван');

SELECT SCOPE_IDENTITY();
```

`SCOPE_IDENTITY()` позволяет получить последнее значение `IDENTITY`, созданное в текущей области выполнения.

# Ограничение количества строк

В PostgreSQL мы могли написать:

```sql
SELECT *
FROM Students
LIMIT 10;
```

В SQL Server используется другой синтаксис:

```sql
SELECT TOP 10 *
FROM college.students;
```

Например:

```sql
SELECT TOP 3 *
FROM college.students;
```

Это одна из простых, но часто встречающихся разниц между СУБД.

В дальнейшем существуют и другие варианты ограничения и постраничного получения данных, но сейчас достаточно запомнить `TOP`.

# Получение текущей даты и времени

В SQL Server существуют функции для получения текущих даты и времени.

Например:

```sql
SELECT GETDATE();
```

Также существует:


На данном этапе важно просто знать, что SQL Server предоставляет собственные функции для работы с текущими датой и временем.

# Работа с `NULL`

В SQL Server часто используется функция:

```sql
ISNULL()
```

Она позволяет заменить `NULL` другим значением.

Например, есть таблица:

```text
students
```

и у некоторых студентов телефон не указан:

| Name    | Phone |
| ------- | ----- |
| Иван    | +7... |
| Мария   | NULL  |
| Алексей | +7... |

Запрос:

```sql
SELECT
    name,
    phone
FROM college.students;
```

может вернуть:

```text
Иван       +7...
Мария      NULL
Алексей    +7...
```

Можно заменить `NULL`:

```sql
SELECT
    Name,
    ISNULL(phone, N'Телефон не указан') AS phone
FROM college.students;
```

Теперь результат будет выглядеть понятнее.

# Что такое `GO`

При работе в SSMS вы часто будете встречать:

```sql
CREATE DATABASE CollegeDB;
GO

USE CollegeDB;
GO

CREATE TABLE college.students
(
    id INT IDENTITY(1,1) PRIMARY KEY,
    name NVARCHAR(100) NOT NULL
);
GO
```

Важно:

> `GO` не является обычной инструкцией T-SQL.

Это разделитель пакетов команд, который используется клиентскими инструментами, например SSMS.

То есть `GO` говорит инструменту:

> Заверши текущий пакет инструкций и отправь его серверу.

Но в SQL-скриптах SQL Server эта конструкция встречается настолько часто, что её необходимо узнавать.

Перейдём в неё:

```sql
USE CollegeDB;
GO
```

Создадим схему:

```sql
CREATE SCHEMA college;
GO
```

Создадим таблицу:

```sql
CREATE TABLE college.students
(
    id INT IDENTITY(1,1) PRIMARY KEY,
    name NVARCHAR(100) NOT NULL,
    age INT NOT NULL
);
GO
```

Добавим студентов:

```sql
INSERT INTO college.students (name, age)
VALUES
    (N'Иван', 18),
    (N'Мария', 17),
    (N'Алексей', 18);
GO
```

Получим данные:

```sql
SELECT *
FROM college.students;
```

Результат будет примерно таким:

| Id | Name    | Age |
| -: | ------- | --: |
|  1 | Иван    |  18 |
|  2 | Мария   |  17 |
|  3 | Алексей |  18 |

Теперь попробуем использовать T-SQL.

```sql
DECLARE @studentCount INT;

SELECT @studentCount = COUNT(*)
FROM college.Students;

SELECT @studentCount AS StudentCount;
```


```text
college.students
```

с полями:


* `id` — первичный ключ;
* `id` должен автоматически увеличиваться;
* `name` — обязательное поле;
* `name` — целое число;
* для имени используйте `NVARCHAR`.
