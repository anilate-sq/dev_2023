# Что такое SSMS

**SQL Server Management Studio (SSMS)** — графическая среда для работы с Microsoft SQL Server.

С помощью SSMS можно:

* подключаться к SQL Server;
* создавать базы данных;
* создавать таблицы;
* выполнять SQL-запросы;
* изменять структуру базы;
* просматривать данные;
* создавать процедуры и функции;
* управлять пользователями и правами;
* анализировать ошибки.

По сути, SSMS — это основной инструмент, через который мы будем взаимодействовать с SQL Server.

# Подключение к SQL Server

После запуска SSMS появляется окно подключения.

Обычно необходимо указать:

```text

Server name
Authentication
```

Например:

```text
Server type:
Database Engine

Server name:
localhost

Authentication:
Windows Authentication
```

После нажатия:

```text
Connect
```

SSMS подключается к SQL Server.

---

# Server Name

В поле:

```text
Server name
```

не обязательно указывать именно:

```text
localhost
```

Имя зависит от того, какой экземпляр SQL Server установлен.

Например:

```text
localhost
```

или:

```text
.\SQLEXPRESS
```

или:

```text
COMPUTER-NAME\SQLEXPRESS
```

Здесь важно понимать:

```text
Компьютер
    │
    └── SQL Server Instance
```

SSMS подключается именно к экземпляру SQL Server.

# Authentication

SQL Server поддерживает разные способы аутентификации.

На учебном компьютере мы чаще всего можем использовать:

```text
Windows Authentication
```

В этом случае SQL Server использует учётную запись Windows.

Также существует:

```text
SQL Server Authentication
```

При этом используются отдельные:

```text
Login
Password
```

Разницу между логинами, пользователями и правами доступа мы подробно рассмотрим позже.

Сейчас главное — уметь подключиться к серверу.

# Создание базы данных через SSMS

Базу данных можно создать двумя способами.

Первый вариант — через графический интерфейс.

В Object Explorer:

```text
Databases
    ↓
ПКМ
    ↓
New Database...
```

После этого откроется окно создания базы данных.

В поле имени можно указать:

```text
CollegeDB
```

После нажатия:

```text
OK
```

SQL Server создаст базу данных.

---

# Создание базы данных через T-SQL

Второй вариант — написать SQL-команду самостоятельно.

```sql
CREATE DATABASE CollegeDB;
GO
```

После выполнения:

```text
Databases
    │
    └── CollegeDB
```

появится новая база.

Если база не появилась сразу в Object Explorer, можно обновить список:

```text
ПКМ по Databases
        ↓
Refresh
```

---

# Почему лучше знать оба способа?

Графический интерфейс удобен для знакомства и отдельных операций.

Но разработчик часто работает со скриптами.

Например:

```sql
CREATE DATABASE CollegeDB;
GO
```

Преимущества скрипта:

* его можно сохранить;
* повторно выполнить;
* передать другому разработчику;
* хранить в Git;
* использовать для автоматического развёртывания базы.

Поэтому в дальнейшем мы будем преимущественно использовать **T-SQL**.

# Создание таблицы

Теперь создадим таблицу студентов.

```sql
CREATE TABLE college.students
(
    id INT IDENTITY(1,1) PRIMARY KEY,
    name NVARCHAR(100) NOT NULL,
    age INT NOT NULL
);
GO
```

Разберём таблицу:

```text
college.students
│       │
│       └── таблица
│
└── схема
```

---

# Разбираем поля таблицы

Поле:

```sql
id INT IDENTITY(1,1) PRIMARY KEY
```

означает:

```text
id
↓
INT
↓
IDENTITY
↓
PRIMARY KEY
```

То есть:

* `id` — имя столбца;
* `INT` — целое число;
* `IDENTITY(1,1)` — автоматическая генерация значений;
* `PRIMARY KEY` — первичный ключ.

---

# Поле name

```sql
name NVARCHAR(100) NOT NULL
```

Здесь:

```text
name
```

— имя столбца.

```text
NVARCHAR(100)
```

— строка длиной до 100 символов.

```text
NOT NULL
```

— значение обязательно должно быть указано.

Например:

```text
Иван
Мария
Алексей
```

можно сохранить.

А:

```text
NULL
```

нельзя.

---

# Поле age

```sql
age INT NOT NULL
```

означает:

```text
age
↓
целое число
↓
обязательно
```

Например:

```text
17
18
19
```

подходят.

А:

```text
"восемнадцать"
```

не является значением типа `INT`.

---

# Ограничения таблицы

При создании таблиц мы можем использовать ограничения.

Наиболее важные:

```text
PRIMARY KEY
FOREIGN KEY
NOT NULL
UNIQUE
CHECK
DEFAULT
```

Они позволяют задавать правила для данных.

Например:

```sql
age INT CHECK (age >= 16)
```

Теперь SQL Server не позволит добавить студента с возрастом:

```text
12
```

---

# PRIMARY KEY

Первичный ключ однозначно идентифицирует строку.

Например:

```text
id
--
1
2
3
```

У каждого студента должен быть уникальный идентификатор.

Поэтому:

```sql
id INT PRIMARY KEY
```

означает:

> Значение `id` является первичным ключом таблицы.

В нашей таблице используется:

```sql
id INT IDENTITY(1,1) PRIMARY KEY
```

---

# UNIQUE

Ограничение `UNIQUE` запрещает повторяющиеся значения.

Например:

```sql
email NVARCHAR(255) UNIQUE
```

Тогда два разных студента не смогут иметь один и тот же email.

Например:

```text
ivan@example.com
maria@example.com
```

можно использовать.

А два раза:

```text
ivan@example.com
```

добавить нельзя.

---

# DEFAULT

`DEFAULT` задаёт значение по умолчанию.

Например:

```sql
is_active BIT DEFAULT 1
```

Если значение не указать:

```sql
INSERT INTO college.students (name, age)
VALUES (N'Иван', 18);
```

SQL Server автоматически использует:

```text
is_active = 1
```

---

# Добавление данных

После создания таблицы можно добавить данные.

Используем:

```sql
INSERT INTO college.students (name, age)
VALUES
    (N'Иван', 18),
    (N'Мария', 17),
    (N'Алексей', 18);
```

Обратите внимание:

`id` мы не указываем.

SQL Server создаст его автоматически благодаря:

```sql
IDENTITY(1,1)
```

---

# Проверяем данные

Используем:

```sql
SELECT *
FROM college.students;
```

Получим примерно:

| id | name    | age |
| -: | ------- | --: |
|  1 | Иван    |  18 |
|  2 | Мария   |  17 |
|  3 | Алексей |  18 |

---

# SELECT с указанием столбцов

Не всегда необходимо получать все столбцы.

Вместо:

```sql
SELECT *
FROM college.students;
```

можно написать:

```sql
SELECT id, name
FROM college.students;
```

Результат:

| id | name    |
| -: | ------- |
|  1 | Иван    |
|  2 | Мария   |
|  3 | Алексей |

Такой вариант обычно лучше показывает, какие именно данные мы хотим получить.

---

# WHERE

Мы можем использовать условие:

```sql
SELECT *
FROM college.students
WHERE age >= 18;
```

Теперь SQL Server вернёт только студентов старше или равных 18 годам.

Например:

| id | name    | age |
| -: | ------- | --: |
|  1 | Иван    |  18 |
|  3 | Алексей |  18 |

---

# UPDATE

Для изменения существующих данных используется:

```sql
UPDATE
```

Например:

```sql
UPDATE college.students
SET age = 19
WHERE id = 1;
```

Теперь студент с:

```text
id = 1
```

будет иметь возраст:

```text
19
```

---

# Почему WHERE особенно важен?

Рассмотрим:

```sql
UPDATE college.students
SET age = 19;
```

Здесь отсутствует:

```sql
WHERE
```

Поэтому значение:

```text
age = 19
```

будет установлено **для всех строк таблицы**.

То же самое относится к:

```sql
DELETE
```

Поэтому перед выполнением `UPDATE` или `DELETE` необходимо внимательно проверять условие.

---

# DELETE

Для удаления строки используется:

```sql
DELETE
```

Например:

```sql
DELETE FROM college.students
WHERE id = 2;
```

Будет удалён студент:

```text
id = 2
```

Остальные строки останутся.

---

# Опасность DELETE без WHERE

Запрос:

```sql
DELETE FROM college.students;
```

удалит все строки таблицы.

Сама таблица при этом останется.

То есть:

```text
Таблица
    ↓
остаётся

Данные
    ↓
удаляются
```

Поэтому `DELETE` без `WHERE` нужно использовать только тогда, когда действительно необходимо удалить все записи.

---

# CREATE TABLE и изменение таблицы

Иногда структура таблицы уже создана, но нам необходимо добавить новый столбец.

Например:

```sql
ALTER TABLE college.students
ADD email NVARCHAR(255);
```

Теперь таблица содержит:

```text
id
name
age
email
```

Для изменения существующей структуры используется:

```sql
ALTER TABLE
```

---

# Удаление столбца

Если столбец больше не нужен:

```sql
ALTER TABLE college.students
DROP COLUMN email;
```

После этого:

```text
email
```

будет удалён из структуры таблицы.

Следует помнить, что удаление столбца может привести к потере содержащихся в нём данных.

---

# Удаление таблицы

Для удаления самой таблицы используется:

```sql
DROP TABLE college.students;
```

После этого:

```text
college.students
```

перестаёт существовать.

Разница:

```text
DELETE
↓
удаляет данные

DROP TABLE
↓
удаляет таблицу
```

---

# DELETE, TRUNCATE и DROP

Эти команды часто путают.

| Команда          | Что происходит            |
| ---------------- | ------------------------- |
| `DELETE`         | удаляет строки            |
| `TRUNCATE TABLE` | быстро удаляет все строки |
| `DROP TABLE`     | удаляет саму таблицу      |

Например:

```sql
DELETE FROM college.students;
```

Удаляет строки.

```sql
TRUNCATE TABLE college.students;
```

Удаляет все строки таблицы.

```sql
DROP TABLE college.students;
```

Удаляет таблицу.

На данном этапе главное — понимать разницу между ними.

---

# GO и выполнение скрипта

При работе в SSMS мы часто будем писать:

```sql
CREATE DATABASE CollegeDB;
GO

USE CollegeDB;
GO

CREATE SCHEMA college;
GO
```

`GO` разделяет отдельные пакеты команд.

Важно помнить:

```text
GO
```

не является обычной инструкцией T-SQL.

Его обрабатывает клиентский инструмент, например SSMS.

---

# Один большой скрипт

Теперь соберём создание базы в один скрипт.

```sql
CREATE DATABASE CollegeDB;
GO

USE CollegeDB;
GO

CREATE SCHEMA college;
GO

CREATE TABLE college.students
(
    id INT IDENTITY(1,1) PRIMARY KEY,
    name NVARCHAR(100) NOT NULL,
    age INT NOT NULL
);
GO

INSERT INTO college.students (name, age)
VALUES
    (N'Иван', 18),
    (N'Мария', 17),
    (N'Алексей', 18);
GO

SELECT *
FROM college.students;
```

Это уже полноценный небольшой сценарий создания базы.

---

# Просмотр данных через SSMS

SSMS позволяет просматривать данные не только через `SELECT`.

Можно нажать правой кнопкой по таблице:

```text
college.students
```

и выбрать:

```text
Select Top 1000 Rows
```

SSMS автоматически создаст запрос примерно такого вида:

```sql
SELECT TOP (1000)
       [id],
       [name],
       [age]
FROM [CollegeDB].[college].[students];
```

Это удобный способ быстро посмотреть содержимое таблицы.

---

# Полное имя объекта

В автоматически созданном запросе можно увидеть:

```text
[CollegeDB].[college].[students]
```

Это:

```text
Database.Schema.Object
```

То есть:

```text
CollegeDB
   ↓
college
   ↓
students
```

Квадратные скобки:

```sql
[CollegeDB].[college].[students]
```

используются SQL Server для обозначения идентификаторов.

---

# Квадратные скобки

В SQL Server можно встретить:

```sql
SELECT *
FROM [college].[students];
```

Квадратные скобки позволяют явно указать имя объекта.

Например:

```sql
SELECT *
FROM [Order];
```

Если имя объекта совпадает с ключевым словом SQL, использование квадратных скобок может быть необходимо.

Но обычно лучше давать объектам понятные имена, которые не конфликтуют с ключевыми словами.

---

# Типичные ошибки

При работе с SQL Server ошибки будут встречаться постоянно.

Это нормально.

Например, если таблица не существует:

```sql
SELECT *
FROM college.students;
```

SQL Server сообщит, что объект не найден.

Причина может быть в том, что:

```text
таблица не создана
```

или:

```text
выбрана неправильная база
```

или:

```text
указана неправильная схема
```

---

# Ошибка неправильной базы

Предположим, мы находимся в:

```text
master
```

и выполняем:

```sql
SELECT *
FROM college.students;
```

SQL Server будет искать:

```text
master.college.students
```

а не:

```text
CollegeDB.college.students
```

Поэтому перед выполнением запроса необходимо проверить текущую базу.

Можно выполнить:

```sql
USE CollegeDB;
GO
```

---

# Ошибка неправильной схемы

Допустим, таблица была создана:

```sql
CREATE TABLE college.students
(
    id INT
);
```

А затем мы выполняем:

```sql
SELECT *
FROM dbo.students;
```

SQL Server ищет:

```text
dbo.students
```

но таблица находится в:

```text
college.students
```

Это разные объекты.

Поэтому всегда обращайте внимание на:

```text
Schema.Object
```

---

# Ошибка при добавлении NULL

Если столбец создан так:

```sql
name NVARCHAR(100) NOT NULL
```

то такой запрос:

```sql
INSERT INTO college.students (age)
VALUES (18);
```

будет ошибочным.

Почему?

Потому что:

```text
name
```

обязателен.

Мы не указали его значение.

# Ошибка типа данных

Если столбец:

```sql
age INT
```

то попытка записать:

```sql
N'восемнадцать'
```

приведёт к ошибке преобразования типов.

Например:

```sql
INSERT INTO college.students (name, age)
VALUES
    (N'Иван', N'восемнадцать');
```

SQL Server ожидает:

```text
INT
```

а получает:

```text
NVARCHAR
```

---

# Как правильно работать с ошибками

Если запрос завершился ошибкой, не нужно просто переписывать его случайным образом.

Нужно определить:

```text
Что хотел сделать запрос?
        ↓
На каком месте произошла ошибка?
        ↓
Что именно сообщает SQL Server?
        ↓
Какой объект или значение вызвало проблему?
```

Со временем сообщения SQL Server станут достаточно понятными.

# Итоговый скрипт

Ниже находится минимальный рабочий скрипт нашей базы:

```sql
CREATE DATABASE CollegeDB;
GO

USE CollegeDB;
GO

CREATE SCHEMA college;
GO

CREATE TABLE college.students
(
    id INT IDENTITY(1,1) PRIMARY KEY,
    name NVARCHAR(100) NOT NULL,
    age INT NOT NULL
);
GO

INSERT INTO college.students (name, age)
VALUES
    (N'Иван', 18),
    (N'Мария', 17),
    (N'Алексей', 18);
GO

SELECT *
FROM college.students;
```

После выполнения мы должны получить:

```text
CollegeDB
    │
    └── college
        │
        └── students
```

и три записи:

| id | name    | age |
| -: | ------- | --: |
|  1 | Иван    |  18 |
|  2 | Мария   |  17 |
|  3 | Алексей |  18 |
